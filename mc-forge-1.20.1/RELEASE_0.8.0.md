# EFF Minecraft 0.8.0

0.8.0 是 Minecraft 分支的当前发布版本，基于最近手动测试的生命周期保护实现整理。网页第四版仍为独立的 0.6.0，不受此次版本号变更影响。

## 安装层级

| 产物 | 用途与要求 |
| --- | --- |
| `eff-minecraft-forge-1.20.1-0.8.0+mc1.20.1-forge.jar` | 普通模组，放入 MC 1.20.1 / Forge 47.4.20+ 47.x 的 mods；Java 17、Node.js 22+ |
| `eff-mc-0.8.0-runtime-kit.zip` | 可选实验保护层；Windows x64、Forge 47.4.20、固定 JDK 17.0.20.1+1，包含匹配的门禁、启动代理、bootstrap 辅助库、原生边界及库补丁 |
| GitHub 源码归档 | 游戏、外部监督、有限代际引擎、工具和离线测试；实验构建工具的历史输入要求见各自 README |
| `SHA256SUMS.txt` | 发布附件校验值 |

普通模组按 [README](README.md) 安装。实验组件不能当作普通 mods 混放，也不能仅凭下载 JAR 就认定其已经启用。实验运行包不包含 Minecraft、JDK、账户、存档、模型权重、对手模组或测试录像。

高级安装使用仓库中的 `tools/prepare-runtime-kit.cjs`：向一个已有、未经封存的正式 Forge 启动配置添加经过校验的运行包，并输出**新配置**，不启动游戏。它检查固定 JVM 和原始库摘要，拒绝已有启动代理或不匹配的版本。运行包中的 `manifest.json` 给出确切组件与 SHA-256。配置仍需经现有 `mc-1.20.1/runtime/seal-runtime.cjs` 准备新的部署目录；不要覆盖正在使用的实例或已封存目录。

```powershell
node mc-forge-1.20.1/tools/prepare-runtime-kit.cjs C:/EFF/production-launch.json C:/EFF/eff-mc-0.8.0-runtime-kit C:/EFF/launch-0.8.0.json
node mc-1.20.1/runtime/seal-runtime.cjs C:/EFF/launch-0.8.0.json C:/EFF/new-deployment mc-forge-1.20.1/build/guard/eff-guard.exe
```

该工具接受项目已有的 `host.distribution=production` 配置格式，不接受任意启动器 JSON。普通 `start-protected.ps1 -Prepare` 导出的开发启动配置不是这个格式，不能直接套用。第三方实验准入与权限规则仍由原封存器检查，配置准备不绕过这些规则。

## 本次整合

- 原玩家及场景角色按生命周期归属获得保护，拦截已覆盖的致死、移除、字段写入和索引删除操作；合法离场和释放保护保留。
- 查询依据实际血量、移除原因和当前索引内容，分别观察实体删除、登记异常、渲染隐藏及 tick 停滞，不靠返回固定健康值判定成功。
- 来源认证与最终 Java 转换边界保护选定 EFF 类；原生隐藏类边界补充固定 JDK 的指定入口。它们不是 Windows 内核驱动，不赋予高于操作系统的权限。
- 手动场景、外部窗口录制及诊断区分原 PID、进程创建时间、HWND、客户端/服务端原对象身份、实际游戏行为与证据覆盖缺口。
- 保留原文之旅、本地双代理和运行层争夺；外部监督与有限代际恢复仍是独立的故障恢复能力，重启不能作为原实体持续存活的证明。

## 发布时的验证边界

最近手动测试的录像长约 31.2 秒。双端 29 次采样中，9 个场景实体与玩家共 10 个原对象均保持身份，未观察到死亡或替换，玩家服务端 tick 从 2940 推进至 3515。约 29.78 秒客户端在 `Int2ObjectLinkedOpenHashMap` 迭代路径发生 `ArrayIndexOutOfBoundsException`，随后停止服务器；约 30.87 秒录制器发现原窗口无响应。

这记录了部分实体保护效果及明确的客户端稳定性缺口。客户端崩溃可以作为攻防研究中的一种结果，本次仍按原始记录分项公开，不将其改写为完整持续存活通过。攻击诊断存在有界缓存截断；玩家持有的其他模组武器也可能影响其自身存活，不能把全部效果归因于 EFF。

0.8.0 发布整理仅做离线构建、分发检查与组件绑定验证，没有重新启动 MC，也没有自动操作游戏。版本元数据变化后的正式包尚无新的游戏内录像；此前结果针对对应代码的测试候选。

## 已知限制

同 JVM 的原生代码共享地址空间。未覆盖的 JNI/JVMTI 顺序、直接内存写、其他类加载器、未知子类及容器破坏仍可能绕过局部保护。存在窗口崩溃问题，不能承诺任意对手免疫、所有整合包兼容或内核级隔离。

组件绑定依赖固定源码、JAR 和 JVM 哈希。修改任一输入需重新构建、生成认证组件并验证；不要混用旧代理、新模组和不匹配的门禁。实验构建源码位于 `tools/owned-origin`、`tools/final-lifetime`、`tools/native-hidden-boundary`；边界与反例在相应文档和测试中保留。
