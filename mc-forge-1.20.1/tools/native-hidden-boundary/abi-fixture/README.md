# Instrumentation JNI ABI compatibility fixture

`../native/instrumentation-abi.h` is a header-only, process-local compatibility adapter. Include it in the trusted native component and call `eff_instrumentation_abi::install(env, jvmti)` once in the JVMTI start/live phase, outside an event callback. Treat a false result/pending exception as installation failure. No additional native libraries or compiler flags beyond C++17 and the JDK JNI/JVMTI headers are required.

It changes only the `CallObjectMethodV` entry obtained through the supported JVMTI function-table API. It matches the cached `InstrumentationImpl.transform` method ID and receiver type before examining the first five valid reference arguments. Correct modern calls retain the original call path and original varargs. The undersupplied legacy shape is adapted using `CallObjectMethodA`, preserving all five supplied object references. It neither reads missing trailing arguments nor edits the sample or public Java method body.

The missing selector cannot be inferred from class redefinition alone. The adapter snapshots both current transformer-manager arrays under the same lock order used by registration. Exactly one nonempty manager determines the selector; two nonempty managers or unknown state produce an explicit compatibility exception. When both are empty, it returns null (no transformation), matching original dispatch semantics and counting the event. This rejects ambiguity instead of silently disabling callbacks. Concurrent registration after the snapshot remains possible, just as with the underlying dispatch snapshot; this mechanism does not claim to reconstruct an intrinsically absent selector for arbitrary mixed registrations.

For initial definitions, module lookup uses `GetNamedModule(loader, package)`; the existing Java implementation supplies the unnamed module fallback. Redefinition passes null and lets the original Java implementation derive the module from the actual Class.

Run `C:\Python314\python.exe mc-forge-1.20.1/tools/native-hidden-boundary/abi-fixture/run.py` from the repository. It compiles a small test DLL and self-generated Java callbacks, then starts a private JDK17 fixture process. It never loads Minecraft, a mod sample, or attack code. Logs and a hashed receipt are saved to a new `output/eff-local-native-20261104/instrumentation-abi-fixture-*` directory; no existing files are deleted.

Coverage includes modern seven-argument identity and selector preservation, legacy five-argument callback execution, ordinary/capable manager selection, null loader/name, named and unnamed module resolution, redefined Class identity, ambiguous-manager refusal, empty-manager no-op, unknown-shape refusal, unchanged transformer-exception semantics, unrelated JNI methods, and a newly created thread's JNI environment.

TransformerManager intentionally catches transformer exceptions and returns null. The fixture checks that the compatibility adapter preserves this original behavior, while its own ambiguity exception reaches the caller. This is compatibility validation, not proof of game startup or successful defense.

The [JVMTI 17 specification](https://docs.oracle.com/en/java/javase/17/docs/specs/jvmti.html#SetJNIFunctionTable) defines function-table replacement for current and future JNI environments and warns that cached/optimized direct calls may bypass it. The audited callback reloads its function-table entry on each call, so that caveat does not apply to this callsite. This does not extend the guarantee to arbitrary native callers or later table replacement by another agent.
