# Explicit owned-class origin boundary

This optional offline candidate adds an outer boundary to the existing ModLauncher defining-loader-context wrapper. It is not a plugin filter. Every authenticated input still enters the original complete pipeline. On successful return, only explicitly selected EFF classes return their authenticated pre-pipeline bytes; all other classes return the pipeline result unchanged. Pipeline exceptions retain their identity and the existing context-loader restoration.

The reviewed roots are enumerated explicitly in `OwnedOriginPatch.ROOTS`. They include the raw state/index readers, original player lifetime registry, arena, render boundary, bootstrap/runtime support, and manual/automated observers. The v65l candidate also includes `client.Pig2EngagementProbe` and the nested manual contexts of `lab.AttackTraceBridge`; the generated receipt and manifest give the actual root/class count for each immutable candidate. There is no whole-`eff` or Minecraft exemption. Observers remain diagnostic only: authenticating their class bytes does not establish the truth of in-process observations or turn missing attack evidence into acceptance.

Build with `node mc-forge-1.20.1/tools/owned-origin/build-and-test.cjs [reobfuscated-eff.jar] [expected-eff-sha256]`. The source ModLauncher is pinned to the previously reviewed v38 library. The EFF input is copied and hashed before use, with input immutability checked again at completion. The result contains a compiled immutable class-name-to-SHA-256 table, source EFF JAR SHA, and an archive of those exact class bytes. It is published only to a private content-addressed output folder; nothing is installed, launched, or downloaded.

An optional final `[base-library-receipt.json]` selects a reviewed plugin-registry build. The builder verifies the pinned original stock ModLauncher and both receipt hashes before applying the owned wrapper. This supports the generic Launcher owner-read binding for constructor-skipped handler replacements without dropping the previously verified plugin or loader-context behavior.

Authentication hashes a private clone before plugins execute. A wrong same-name input throws a bounded `SecurityException`. The private snapshot is not passed to plugins, and successful protected output is a fresh clone. The first successful completion per selected class logs the class name, input/transformed/output SHA-256, and whether the pipeline changed its bytes. No byte arrays or arbitrary exception messages are logged.

Compatibility is deliberately narrow. The v39 ProjectionProbe removes its previous static Mixin accessor invocation. The builder rejects Mixin/Fabric dependencies and runtime annotations in selected classes; validates MC references as SRG names, the inherited Java Object/Executor APIs, or enum fields actually present in the reviewed MC JARs; and selects no Mixin/accessor/event-registration classes. It preserves existing method bodies/class metadata and all other library entries. Reversing the one wrapper addition must reconstruct the original parsed loader class exactly. Baseline game verification is still required: static checks do not prove every future Forge transformation is unnecessary.

Tests execute the actual new and existing context wrappers under `-Xverify:all`; only their innermost plugin delegate is replaced by a synthetic callback. A real EFF RawHealthProbe method is changed to an early return and its input array is overwritten; the returned protected implementation executes the original behavior. Tests also prove wrong-hash refusal, no array aliasing, original exception identity, unchanged TCCL restoration, exact propagation of changed real Minecraft Entity bytes, and unchanged propagation of the original sample's transformer class bytes. The sample's native-dependent entry is not executed, so this is not an assertion that original sample combat passed.

This is an initial class-definition boundary. Later Instrumentation/JVMTI/native redefinition, direct memory modification, or modification of the boundary itself can bypass it. It does not establish kernel-level immunity or entity survival, and a restart remains a failed survival test.
