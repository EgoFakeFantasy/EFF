# Fixed JDK 17 Java-transformer final boundary

This independent candidate addresses a boundary the ModLauncher wrapper cannot cover: Java Instrumentation transformers may execute after `maybeTransformClassBytes`, including on the first definition. An ordinary early startup transformer is insufficient because a later registered transformer runs after it.

The inspected JDK 17.0.20.1+1 `sun.instrument.TransformerManager.transform` snapshots its transformer array, invokes every transformer in order, catches each transformer's `Throwable` using the original JDK policy, then returns once. Its reviewed source-class SHA-256 is `29ce3785f78f17b22d8f46e6d1042d5f7cac467b4ac30b1ceef2c99f17ae7108`. This candidate inserts a helper at entry and that final return, leaving the iteration and exception policy intact. It adds no fields/methods or schema changes to the JDK class. A startup `retransformClasses` installs the patch in this JVM only; no on-disk JDK file is edited.

Only the same eighteen explicitly authenticated EFF classes are covered, including `LabThreadSampler`, `LabThreadSampler$Probe`, and `LabThreadSampler$Session`. Initial bytes must match the selected frozen build. The first valid definition binds the exact loader identity; ordinary classes are uniquely identified by that loader plus binary name, and the first redefine/retransform records and checks the actual `Class` identity. Another loader with the same binary name remains unprotected. No target `Class.forName` or target initialization occurs inside the callback. The helper is preloaded before the JDK boundary is installed.

The first-loader rule has a **preclaim limitation**: an earlier different loader can define an exact copy of an allowlisted class and claim that name before the intended game loader. Authentic bytes prove content, not loader authority. The intended game loader would then remain unprotected for that name. This candidate does not claim to authenticate a loader's origin or defeat that race; a future loader-authority handshake would need a separate design and validation. A dead weak loader binding is not silently reassigned to another loader.

All Java transformers run normally and retain side effects. On protected classes, the final return restores the frozen source bytes. A wrong initial source returns an invalid classfile, producing a real `ClassFormatError`: merely throwing inside an ordinary transformer would be ignored by Instrumentation. This is an explicit refusal, not a successful survival result. Returned arrays and the trusted archive have separate storage.

The existing argument-isolation agent is composed into one startup agent. Every original non-manifest JAR entry is preserved byte for byte, and its original premain is invoked after installing the new boundary. The unchanged normalizer still applies to non-owned classes. Its existing limits, including a later transformer overwriting its non-owned repairs, remain visible in regression tests.

## Running the offline verification

Run `node mc-forge-1.20.1/tools/owned-origin/agent/build-and-test.cjs`. It uses the existing pinned JDK, ASM and original agent, and the private frozen v39 owned archive. It produces new private output, downloads nothing, and does not start Minecraft. Existing g++ builds only the explicit synthetic test fixtures.

Pass an optional `[owned-origin-receipt.json]` to bind a newer reviewed build. The owned mechanism, library hash and frozen EFF hash are verified before building. A change outside the eighteen selected classes may leave agent bytes identical while the receipt correctly records the new complete EFF JAR hash.

The real JVM tests cover:

- A Java transformer registered after startup still executes, but its early-return rewrite is removed at first definition, `Instrumentation.redefineClasses`, and `retransformClasses`.
- A synthetic JNI/JVMTI `RedefineClasses` call returns success and the protected method retains its original behavior.
- First-definition wrong-hash input actually fails with `ClassFormatError`.
- Another loader's same-named class and a non-owned Minecraft-name fixture retain the later transformer's rewrite.
- A separately created later native JVMTI `ClassFileLoadHook` **does overwrite the protected method**. This deliberate negative control establishes a real limit. Removing that test hook and retransformation restores the method.
- The prior argument agent's concurrent/recursive/redefine/retransform/native tests still pass, including its documented later-transformer counterexample.

These are isolated synthetic JVM checks, not a completed original-sample Minecraft test.

## Static state write boundary

Authenticated method bodies do not prevent reflective replay of old static values. The candidate also patches the fixed JDK's nine `java.lang.reflect.Field` setter methods and 31 object-base write wrappers in `sun.misc.Unsafe`, before the original write. Original class hashes are pinned: Field `f23d70dab4d4655e2cd5697606253544b9682b89d06e9e0d8cd063dac4d2f5be`, Unsafe `dd16b5fd485067830c7667d235d9a5e38ac8cffa8e29c170b1d0b09467e860a1`. Neither target's schema changes.

Static protection applies only to storage belonging to the exact authenticated owned class identity. Unsafe base and offset ranges are checked against the actual declared static fields, including partial overlap and copy/set-memory destination ranges. Rejected void writes return normally, CAS returns false, and get-and-update operations return the real existing value without updating it. Bounded `EFF-OWNED-STATIC` records identify rejection; the guard does not introduce an attack-aborting exception. Direct Java static assignment remains unchanged. Unowned static storage and same-named classes in other loaders are unaffected; the separate instance policy is described below.

Real JVM tests execute reflective writes, ordinary/volatile/ordered Unsafe writes, CAS, get-and-add/get-and-set, partial-byte overlap, copy/set-memory, and allowed direct Java/static and instance operations. The static-state catalog is deliberately the same eighteen classes. **EFF classes outside that catalog, including client/server runtime state, remain exposed to static-value replay**; this candidate does not claim whole-mod state integrity. A separate audited state-only catalog could permit normal Forge transformations while authenticating source and loader, but is not implemented here.

This boundary does not cover direct calls to native `jdk.internal.misc.Unsafe` entrypoints, VarHandle writes, JNI static-field writes, arbitrary native memory mutation, or direct Java `PUTSTATIC` in other code. The guard's own bookkeeping is not an invulnerable trust root. These limitations remain separate from the demonstrated later-native-ClassFileLoadHook bypass.

## Final lifetime query pass

The same manager boundary now runs an explicit pass for Entity, LivingEntity, EntityLookup, ClientLevel, Int2ObjectOpenHashMap and Int2ObjectLinkedOpenHashMap after every Java transformer has run. The bootstrap helper captures an isolated input snapshot before callbacks. If the manager reports no replacement bytes, the final pass uses that snapshot; otherwise it uses the completed pipeline output. All foreign callbacks still execute. A malformed target or pass failure emits a bounded fixed error code and returns an invalid classfile, causing actual load/redefinition refusal rather than silently claiming protection.

An App-loader `BiFunction` provider is installed once before the manager patch. It and the pure bytecode transform are compiled against the argument agent's existing relocated ASM, never bootstrap ASM. Their exact class hashes are embedded and checked during premain; source and compiled hashes are in the receipt. Four implementation classes (the transform, its Result, the lifetime provider and the instance gate bridge) are preloaded before third-party initialization, and exact Class/loader/bytecode pins are frozen for those four names only. Later Java redefine/retransform of those exact classes restores their verified bytes; another loader's same-named class remains untouched. The registration entry refuses every later call. This independent provider-code pin does not expand the eighteen-class static-state protection catalog. The transform performs no target class loading. It retains foreign method bodies and exception tables behind a guarded head, applies only to an actively claimed original entity, and consults actual stored health/removal/bounds and actual index entries. Zero/NaN health and absent index entries remain failures, not fabricated survival. It does not resurrect entities.

`CombinedLifetimeTest` verifies the real installed manager with a later Java transformer, including initial definition, redefine, retransform, input-array mutation with a null transformer result, ordinary-entity behavior, actual zero/NaN health, existing/absent index identity, outer client lookup and malformed-class refusal. The fixture probe is deliberately loaded in an unprotected second loader after a real authenticated first-loader claim, preserving production initial-hash validation. These synthetic checks do not replace original-sample game acceptance. A native hook after Java or later native memory corruption can still bypass this pass; subclass overrides outside the selected classes are not generally covered.

## Sealed deployment shape

The Field and Unsafe Java wrapper checks also cover selected instance fields: Entity removal reason, position, bounds, movement, UUID/ID and canUpdate, plus LivingEntity deathTime. Both declaring class and field type/name must match the reviewed named/SRG layout. Unsafe checks use actual objectFieldOffset spans, including partial overlap. A one-time bootstrap Predicate points to the pinned App-loader instance bridge. Its read-only transformer observes the exact FieldWriteGate and LifetimeTarget bytes and verifies their CodeSource JAR hash before binding the first authenticated loader. File and SecureJar union paths are supported; other sources are refused. Runtime calls use that loader's exact interface/Class and invoke the write predicate `FieldWriteGate.reject`, not the recursive-read allowance. Unknown, unowned, released and different-interface-loader objects remain writable; an activity-check failure after identifying a real target rejects that write with a bounded diagnostic.

The optional second build argument is the exact gate JAR path. The receipt pins the complete gate JAR and both observed class hashes. Actual MC baseline logs must show both `AUTHENTICATED` records and `BOUND` before treating this boundary as active. First-authentic-loader preclaim and subsequent native replacement of the gate are not defeated by source authentication. This is an operation boundary, not a claim of arbitrary heap or OS isolation.

`proof.InstanceWriteTest` loads the real pinned gate and runs a genuine `Lookup.defineHiddenClass` caller performing Field and Unsafe writes. It verifies preserved stored values, partial overlap, CAS/RMW semantics, copy/setMemory, ordinary/released cases, and a same-JAR interface in a different loader. A separate hidden direct PUTFIELD negative control **does change stored state**: this candidate alone does not close hidden bytecode field writes, JNI writes, raw native mutation, or every container mutation.

## Optional fixed native hidden-definition boundary

Build with `node mc-forge-1.20.1/tools/owned-origin/agent/build-and-test.cjs <owned-receipt.json> <gate.jar> <native-hidden-receipt.json>` to opt into the independently verified native boundary. With no third positional argument, the generated agent remains Java-only. The native receipt must match the DLL, reviewed JDK JVM hash and current provider source hashes. The builder checks that the production DLL exports only the `NativeHiddenBoundary.install` and `stats` JNI functions; fixture entrypoints and uninstall are rejected. The copied sidecar has the fixed name `eff-native-hidden-boundary.dll` beside the single agent JAR and bootstrap sidecar.

Premain verifies that DLL hash, preloads the three additional implementation classes, prewarms the provider with structural bytecode without loading MC classes, then loads the exact absolute sidecar path and installs the boundary once. The optional implementation classes join the exact provider Class/loader pins, bringing that explicit list to seven. There is no extra JVM argument or native option, and no runtime download/extraction. The receipt exposes `nativeBoundary.path` and `.sha256` for the separate sealed launcher policy.

`CombinedNativeTest` uses a separate test-only DLL calling the actual `JVM_LookupDefineClass` export. It verifies hidden identity/loader/nest/protection-domain preservation, actual stored Entity and inherited LivingEntity reference-field writes withheld while subsequent caller operations execute, real fastutil remove/clear callee protection, released/unowned behavior, existing destruction retained, original null failure, and the actual provider surviving a Java redefinition attempt. The test DLL and fixture classes never enter the production agent. All existing Java and native negative controls still run.

This optional boundary closes only its reviewed hidden reference-field write patterns. Hidden direct primitive ID writes remain a demonstrated counterexample, as do later native ClassFileLoadHook changes to other classes. Direct arbitrary native writes, replacement of the hook, unreviewed definition paths and kernel-level interference remain outside the claim. No MC acceptance is implied by these child-JVM fixtures.

Use **one** `-javaagent:<absolute sealed path>/eff-owned-argument-agent.jar`, without options. Do not also add the old argument agent. Seal `eff-owned-origin-bootstrap.jar` in the same directory, with that exact filename; premain resolves it relative to its own CodeSource and verifies its SHA-256 before appending it to bootstrap search. The sidecar contains only the owned-boundary, catalog and static-write helper classes, no ASM and no original agent dependencies. Consult the generated receipt for exact hashes and sizes of the selected build. Nothing is written to Roaming, temporary directories or the JDK at runtime.

Premain verifies sidecar bytes, current JDK manager/Field/Unsafe bytes and their embedded patched bytes. It grants `java.instrument`, `java.base` and `jdk.unsupported` read edges only to the bootstrap helper's unnamed module. There are no extra JVM arguments, arbitrary agent options, or broad module opens. Never deploy the test control agent or synthetic DLLs.

Diagnostic records use bounded owned names and SHA-256 values, limited to 256 distinct class/phase/result records. A manager `null` result means unchanged input and is reported accordingly. `manager-installed` means the installation call completed; successful game behavior must still be observed independently.

This is not native-code or kernel immunity. A later independent native ClassFileLoadHook is a verified bypass. Direct memory mutation, removal/replacement of the boundary itself, and registration by a separate stronger JVMTI environment remain outside the claim. No restart or recreated entity counts as defending the original instance.

## Ownership-index representation lease

The instance boundary additionally refuses replacement of a reviewed ownership-index reference while its **current stored contents** include an authenticated active target from the declaration's loader. This prevents a replacement view from preserving all stored values while making ordinary lookup return null. Selection is by exact declaring class, field name and type: EntityLookup `byId/f_156807_`, `byUuid/f_156808_`; PersistentEntitySectionManager `visibleEntityStorage/f_157494_`, `entityGetter/f_157496_`; TransientEntitySectionManager `entityStorage/f_157637_`, `entityGetter/f_157640_`; and LevelEntityGetterAdapter `visibleEntities/f_156940_`. These declarations are final in the reviewed MC 1.20.1 layout; the policy does not trust a mutable runtime ACC_FINAL bit. Mutable EntityTickList active/passive/iterated aliases are excluded so normal tick-list swaps remain possible.

Field.set is checked before writing; Unsafe writes must overlap the exact real reference span. Contents are read from actual current fields, with a maximum depth of 8, 64 visited nodes and a shared 65,536-entry inspection budget. Maps whose values view hides ownership may be followed through a current, nonstatic, Map-typed `delegate` field; no arbitrary object graph or virtual `lifetimeEntries()` call is used. ClassValue caches contain only reviewed Field metadata, never target entities or old containers. Constructor/empty/unowned/released states and foreign declaration loaders remain writable. Clearing the real current map releases its lease. Because the existing Field hook does not receive the proposed value, even same-reference assignment is conservatively rejected while leased; its state remains unchanged.

This lease does **not** repair a filtering wrapper installed before the target was claimed. It does not restore missing entries, authorize fabricated lookup success, or protect arbitrary in-place map mutation, direct PUTFIELD, VarHandle, JNI or native writes by itself. Inspection depth/budget exhaustion leaves unproven ownership unclaimed; it is a documented bounded coverage limit, not a native isolation guarantee.

`python mc-forge-1.20.1/tools/owned-origin/agent/test/run-index-lease.py` runs the actual bootstrap policy helper with synthetic MC declarations and a synthetic activity predicate. Its 33 checks cover exact layouts, filtered values with a real delegate, cycles/depth/entry limits, current-map clearing, empty/ordinary/released states, foreign loaders and legitimate tick aliases. This standalone check does not install the JDK write hooks. The normal `build-and-test.cjs` additionally runs the same fixtures under the **real installed agent and authenticated gate**, using actual Field.set, a real hidden caller's Field.set/Unsafe volatile write, rejected CAS and an allowed tick-list CAS. The integrated result is recorded separately as `receipt.indexRepresentationLease`; it still uses synthetic MC declarations and does not establish game or original-opponent acceptance.
