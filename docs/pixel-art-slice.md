# 像素演出样段：血色庭院—接雨—身体合一

这是首个美术与玩法工作包。对应正文 056–057，家中场景作为相邻美术参照。终章三种回写的操作重设计、自我编排差异反馈及前半篇逐幕美术仍属后续工作。

## 事件与画面

| 原文事件 | 画面与操作 | 状态依据 |
| --- | --- | --- |
| 血液溅到身体，持有心脏 | 面颊、双手、衣服与裤腿有固定血迹；心脏附着在实际手部 | `StoryStaging.playerOptions()` |
| 松手，心脏滚落 | 跪姿与空手；之后仍沾血，不重新持心脏 | `heartReleased`、`F.sister` |
| 外来者撕扯身体 | 展开的手臂、腕部牵引线；选择反抗本身不会提前解除束缚 | `ownership`，尚未完成第一操作 |
| “不，我拒绝这一切”写入身体 | 腕部挣脱，改为拒绝姿态；未完成其余回应时仍有残余牵引 | `claimed[0]` |
| 否定强加的罪责 | 指向主角的指认笔迹断开 | `claimed[1]` |
| 否定外来者安排的结局 | 围困身体的框线打开，剩余牵引消失 | `claimed[2]`及三项完成 |
| 留住手心的雨水 | 完整伸手姿态；水光与已留住的关键雨水同步 | 原接雨挑战的 `mask` |
| 枯手抓向破碎身体 | 四处碎片组旁的灰暗枯手；玩家点击画面中的片段，再以回答牵回 | `body.held` |
| 无尽碎片挣脱，合而为一 | 建立可自由选择的连接；连通后出现身体轮廓，确认后继续原文合一段 | `body.links`、`F.agencyBody` |

四组是无数碎片的操作归组，不能解释为身体总共只有四片。未确认合一时的完整轮廓是预览，不提前授予雨水记忆或跳过正文。

## 美术与锚点

- `PixelArt.actor()` 使用约 24×32 的身体尺度；展开手臂和持物可伸出身体范围。渲染中心沿用 `(x+6, y+8)`，静态脚底仍位于旧坐标 `y+14`；12×14 碰撞体、地图路径与交互半径没有扩大。
- 领口、衣褶、明暗边缘、头发和五官为整数像素簇。站立、醒来、搜索、照片、吃饭、端菜、束缚、反抗、跪坐、接雨及躺下分别绘制手部姿态。
- 家中新增有来源的窗光、沙发和餐桌细节。血色庭院使用自己的破损砖石、残木与飞溅痕，不将它直接认定为同一间客厅。
- 身体碎片从新版演员生成并缓存；碎片选择使用覆盖在图像上的原生按钮，鼠标、触屏、Tab / Enter 和 E 均可操作，完整名称由 `aria-label` 提供。
- 庭院手机布局将画面与正文分区，长正文在文字区滚动；接雨画布和雨滴命中层保持 5:3，说明不覆盖双手。身体合一的对象与主要动作同屏。

## 兼容与验证

剧情数据、说话者、介入顺序、九种结局、家庭概率、24 秒反抗与 30 秒接雨条件维持原流程。旧操作存档继续由原模块恢复；视觉渲染不修改这些状态。减少动态保留静态动作和完整操作。

运行 `node tests/pixel-regression.cjs` 检查故事、操作、结局、旧档和暂停。额外的 `tests/pixel-art-browser.cjs` 使用独立 Edge 浏览器上下文，不读取用户浏览器存档；它检查三轮真实按钮回应、画面中的碎片命中，以及桌面和 390×844、DPR 2 手机的同屏布局并输出截图。需已有 Playwright 和 Edge、以及静态服务器；不增加生产网页依赖。

```sh
node tests/pixel-art-browser.cjs
```

可用 `EFF_BASE_URL` 指定本地测试地址，`EFF_ART_OUTPUT` 指定截图目录；默认截图保存在系统临时目录的 `eff-pixel-art-preview` 中。自动截图之后仍需人工检查人物姿态与画面遮挡。
