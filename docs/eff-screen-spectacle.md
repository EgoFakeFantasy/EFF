# EFF 0.4：全窗口现象演出

日期：2026-10-15。将已经确认的现象攻防呈现为整个游戏窗口的断裂、执行轨迹暴露、黑场与重新显现；终章以同一表现语言呈现语句覆盖和过去回写。

## 演出与实际事件

| 已确认的事件 | 演出 |
| --- | --- |
| 身体执行资格得到回应 | 牵引与整个窗口沿裂缝断开，露出身体资格的实际核验轨迹 |
| 强加归责被拒绝 | 归责链断裂、旧指认随界面碎片移开，证据与受理结果显露 |
| 尚未提交的坏结局被拒绝 | BAD END 05 印记从中间被撕开，窗口碎片分离 |
| 三项回应全部完成 | 旧运行表面崩溃、黑场、从已验证检查点生成下一虚拟运行实例，重新展开同一程序表面 |
| 本轮失守 | 原界面被挤压并落下，新的执行者标记为外来者；主线仍需玩家明确接受占据结果 |
| 保全 / 排序 | 呈现未决事件的保全或移位，不宣告目标已经完成 |

完整重建约 9.2 秒：主张相撞、界面断裂、轨迹显露、黑场、实例重建和回应重新显现。动画进度仅用于表现。规则先在一次事务中提交，随后保存检查点，再开始演出；时间、胜负和证据不由动画推测。

## 窗口与代码的表现

演出使用浏览器顶层 dialog，覆盖地图、原界面和技术面板。把当时实际界面和 Canvas 内容复制为六片被切开的窗口表面，以固定像素坐标位移。复制体移除脚本、链接、表单标识、事件属性和原 ID，保持 inert。源码轨迹使用当前回合的动作、证据、验证结果与前后状态；矩阵背景展示这些有限轨迹。

外来者占据和终章反写使用红紫色，玩家回应使用灰绿与金色。旁白覆盖的原句与替代句完整保留，较长原句可在暂停时滚动查看。程序黑场、窗口重生和代码剥落均发生在游戏窗口中。

## 运行实例重建

`VirtualEngine.instantiate(checkpoint, generation)` 从真实双方提案重放状态；`replace` 要求战斗 ID、revision 和结果与当前实例完全一致。创建新的状态对象与历史数组，实例代数递增，可信仲裁规则仍为 epoch 1。窗口显示 INSTANCE 02 / RULE 1，表达新的运行承载，而不是任意修改可信验证器。

附加实验存档升级 v3，兼容 v1/v2，单独保存实例代数。读档恢复实际已提交状态，不重新生成模型回复或自动重播旧动画。伪造结果、外来战斗、不同 revision 和过量代数会被拒绝。

## 原文的终章映射

- 故事状态 2：原来的“于是，侵略者被赶出”在全窗口中被划断，完整的“然而，这是无能为力的谎言……”以外来者色调覆盖。
- 故事状态 3：新的表象再次争夺发生本身；尚未获授权时，演出不画出过去回写或第三位参与者。
- 周防请求援助之后：无意识的原文插入才出现回指过去的轨迹和新的裂口。
- 章节重写：旧故事表面黑场，重新生成起点的呈现，保留回写后的第一句、原文全部段落及既有结局条件。

原 `combat-script.js` 和 `finale-script.js` 文本不改。演出不会代替三项原文动作、删去正文、提前授予无意识权限，或自动选择接受坏结局。

## 操作、暂停与预览

底部可暂停 / 继续、略过；空格暂停，Esc 略过当前演出。主线探索、反抗期限和正文推进在演出中暂停，失焦、隐藏和阅读工具也暂停演出时间。减少动态开启时显示静态回应，不进行碎片位移和闪光。重启或退出清理投影、输入和动画回调。

主菜单“看看撕裂与重建的演出”以及技术窗口“撕裂演出预览”可直接体验重建。预览用独立有限模拟，不提交剧情、真实战斗回合或结局。

## 画面精化

- 代码层按窗口设备像素绘制（不再把 640×360 拉伸），文字与裂痕保持锐利；几何仍以 640×360 的计划坐标表达。
- 裂痕沿碎片接缝以确定性锯齿路径从冲击点生长，分为外辉光、色芯和高光三层，裂尖带火花；冲击瞬间有光环。
- 执行轨迹以列状滚动暴露，只取本轮 `trace` 的真实行，越靠近冲击点越亮；运行面板逐字打出这些行并去重。
- 结局封印为双框印版，沿锯齿撕裂线分成两半（先平移再裁剪，文字不再重叠成“END END”）。
- 碎片由外层投影照亮断面；崩溃时屏幕像显示器失去信号般收为一线，再亮起 EFF 启动屏；新实例由扫描线点亮；标题在主张相撞时短暂错位。
- 减少动态 / 系统减少动态设置下，以上动画全部关闭，只显示静态回应。
- 本地版主页插画改为 2× 底板：红月有光晕与陨坑、雨塔砖缝与亮窗、旋梯与归来者、斜雨与星光闪烁（减少动态时静止）。

## 验证

- 原流程 100 项回归，以及 37 项规则 / 宿主 / 代理 / 演出计划与运行实例检查。
- 实际 Electron 窗口：全视口覆盖、顶层输入隔离、复制体无脚本和重复 ID、暂停与失焦、真实实例 2 与刷新恢复、完整的终章原句及替代句、章节重建、减少动态与重启清理。
- 实际演出录屏与关键帧由开发专用目录保存；各次窗口使用独立存档。

当前为固定规则下的运行实例重建，不实现任意生成 JS/Wasm 引擎或模型更新仲裁器。后续可在相同信任边界中增加更多受验证规则实例。
