# EFF 0.5：动态世界与运行实例

日期：2026-10-15。在 0.4.1 的全窗口演出之上，将血色庭院与终章接入共同的世界状态、输入、绘图与实例生命周期。参考原生游戏移植中“宿主承载、模块适配、共享渲染”的组织方式；当前适配对象是 EFF 的像素场景与运行骨架。

## 实际运行结构

- `WorldRuntime`：独立的纯数据世界。实验权限来自 `PhenomenonRuntime.replay`；原文庭院来自实际三个回应；终章来自原文当前节点、已授权介入与回写步数。输入、碰撞、角色位置、事件关系均在实例中处理。
- `WorldHost` / `world-worker.cjs`：Electron 主进程只启动固定的可信模块。每个活动世界对应一个 utility 子进程；严格限定数据请求、串行处理并记录生命周期。重建先等待旧进程结束，再启动新进程，恢复同一份已确认状态和角色位置。
- `WorldScenePort`：复用原地图瓦片、场景道具与 PixelArt 角色；以实例坐标同时画像素场景和控制骨架。原地图缓存不被替换。终章的过去锚点与第三位象征像只在原文授权后出现。
- `WorldCompositor`：以两幅 Canvas 作为 WebGL2 纹理，在同一帧中合成表面、骨架、压力与裂缝。纹理用最近邻采样。GPU 不可用或上下文丢失时，用相同权威帧回退 Canvas 绘图。
- `WorldStage`：为技术窗口、原文场景与全窗口演出统一输入、暂停、帧调度与场景接入。渲染骨架来自当前实例，不按画面猜测胜负。

Electron 的子进程接口见[官方 utilityProcess 文档](https://www.electronjs.org/docs/latest/api/utility-process)，Canvas 纹理接入见[WebGL texImage2D 文档](https://developer.mozilla.org/en-US/docs/Web/API/WebGLRenderingContext/texImage2D)。当前画面仍由外层 GPU 合成器绘制；可替换子进程承载世界逻辑。

## 庭院中的操作与演出

身体尚在争夺时，移动指令不能接管角色，牵引由外来者执行。身体回应成立后，WASD／方向键控制技术窗口和演出中的实际角色。原文庭院可用 WASD 感受同一操控链；左右方向键仍用于原文对象选择，E／空格仍按原文推进。

结局边界参与碰撞：拿回身体后可在边界内移动，单独拒绝结局写入才打开边界。归责链单独显示与断裂。预算耗尽时，即使曾回应身体，执行者也转为外来者，新的结局边界包围当前位置。

原文回应确认后，角色位置同步给原庭院；技术结果只有玩家明确选择回到原文时才带回位置与既有回应流程。练习窗口不改原剧情的位置、旗标、结局与期限。

三项全部成立后，窗口碎片脱离、像素表面显露运行骨架、黑场，再由下一运行实例继续。动画期间的移动由同一世界实例执行；重建保留位置、碰撞边界、已确认权限和有限仲裁规则。

## 终章与叙事约束

原句与替代句仍完整显示。现阶段的两方覆盖、授权后的过去锚点与起点重写由同一事件状态驱动画面；旧的原文过程图、正文选择和全部段落继续工作。过去锚点表示一条发生过程的回写。

未获请求时，数据接口拒绝过去步数与章节重写，也不画第三位参与者。原 `combat-script.js`、`finale-script.js` 不改，全部原结局与时间概率规则保留。

## 暂停、恢复和保存

失焦、隐藏、设置、图鉴、回读与演出暂停都会停止世界步进；释放输入，恢复后没有旧按键继续驱动角色。减少动态保持静态表面，主动移动仍可操作。预览临时承载独立世界，结束后恢复先前世界及位置，不提交玩家的真实回合。

实验存档 v4 兼容 v1–v3，追加位置、朝向、演出时钟与边界锚点。权限仍由仲裁记录重放，位置不能伪造胜负。意外进程退出时保留确认状态并显示“从检查点接续”；恢复不会重做模型生成或接受坏结局。离开场景、重启与退出释放本游戏世界实例。

## 验证范围

原流程 100 项、规则／宿主／代理／演出与世界逻辑 47 项检查。实际窗口检查包括原生子进程、WebGL2、实际输入、暂停、三项独立结果、旧 PID 结束、新 PID 接续、位置重放、刷新、预览隔离、意外终止恢复、GPU 回退与终章权限。

窗口测试使用独立存档，录屏保留并查看关键帧。测试中的意外终止和 GPU 丢失只作用于测试程序自己的子进程与渲染上下文。

当前为固定可信规则和模块下的原生实例切换。更多引擎可按同样的状态／输入／绘图接口增加适配器；任意生成并执行 JS/Wasm、通用商业游戏兼容和整套原探索引擎重写不属于这版交付。
