# EFF 本地版：技术可行性与实施框架

日期：2026-10-14。依据用户提供的《EFF_Repression_AI_Technical_Proposal.md》，以 GitHub main `2acc2ff461dc1e07d0cda9e04e4d60cf7507f2a5` 为代码基线；合并此前尚未发布的角色、庭院及身体合一美术工作包。原工作目录保留。

## 结论与技术选择

可行，但要分开“代理提出策略”和“规则确认结果”。本次交付可独立运行的 Windows x64 本地版，以及 P1/P2 现象战争的实际实现；P3 提供用户已有 Ollama 的可选连接与失败回退。不下载模型，不将未测量的模型大小称为最低硬件要求。Wasm、Rust 仲裁迁移和虚拟引擎演化属于后续阶段。

| 组件 | 选择 | 原因与代价 |
| --- | --- | --- |
| 剧情与像素渲染 | 复用 pixel-version 的经典脚本 | 保留原文、地图、过场、音乐及全部结局，避免重写游戏引擎 |
| 本地窗口 | 固定版本 Electron 44.7.2 | 本机有 Node 24，无 Rust/.NET SDK；可直接构建便携包，代价是需附带 Chromium/Node，包体较大 |
| 资源服务 | `eff://game/` 自定义协议 | 从随包资源读取，无 localhost 游戏服务器；阻止跨目录和外部导航 |
| 本地数据 | 专用配置目录的原子 JSON + 备份 | 普通与技术模式隔离；旧 v1 游戏数据结构保持，支持显式 JSON 导入导出 |
| 现象仲裁 | 纯函数 JavaScript + 数据式 DSL | 提案不执行代码；相同种子和回合记录可重放，未来可按相同协议迁移 Rust |
| 代理 | 固定规则模板 / 可选 Ollama | 无模型也可玩；LLM 只输出建议，未知或无效提案回退模板 |
| 研究模式 | JSON 规则编辑器 | 五种限定动作，拒绝任意 JS、shell、外部文件和进程操作 |

Electron 渲染层采用 `contextIsolation`、`sandbox`、禁用 Node 集成与最小 preload 接口；遵循[官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。资源协议使用[官方 protocol 接口](https://www.electronjs.org/docs/latest/api/protocol)，不开放 file:// 浏览。Ollama 仅在玩家明确开启后向固定 loopback 服务请求[结构化 chat 输出](https://docs.ollama.com/capabilities/structured-outputs)，不自动拉取模型。

## 四层实现与数据流

1. 玩家在原文庭院指控读完后的选择点进入实验；主线倒计时明确暂停，并保存原剧情检查点。
2. 适配器建立只读的冲突事件：身体资格未定、罪责被指认、结局尚未提交。正文与 F/G 不交给模型修改。
3. 玩家选择目标及意志／协作／研究方式。守护侧与外来者各提出数据式提案；模型自由解释不冒充小说台词。
4. 仲裁器校验 schema、battle_id、revision、动作权限、目标与事件证据，并提交一次确定性回合；记录两方的受理／拒绝、状态变化和预算。
5. 三项目标独立，任何一项成功不代替其余两项；规则更换次序不等于回写已经发生的历史。
6. 全部成功后，可以回到周防原文的拒绝与三项写入；所有正文仍需阅读。实验失守可继续原场景，或明确接受占据结果进入既有 BAD END 05。技术结果另记 `tech_court_*`，不新增或覆盖小说结局。
7. 实验在单独存档键保存完整回合。读取时从初始事件重放，而非直接相信文件里的胜负字段。

普通模式不启用实验，不改变 24 秒、正确写入 +5 秒（上限24）与 30 秒接雨。技术模式仅在面板打开时暂停；关闭、设置、失焦与刷新分别验证，不因模型速度改变结局。

## DSL 与确定性语义

| 动作 | 首版语义 |
| --- | --- |
| `REQUEST_AUTHORITY_REVIEW` | 引用身体资格争议事件，核验执行权；不授予历史能力 |
| `CHALLENGE_PRECONDITION` | 用事件证据分别质疑强加罪责或尚未提交的结局 |
| `PROPOSE_EVENT_ORDER` | 调整两项尚未提交的虚拟事件顺序；不能撤销已提交事件 |
| `PRESERVE_CHECKPOINT` | 保留合法的实验检查点；不等于赢得身体或罪责争夺 |
| `CONCEDE_OR_RETRY` | 显式认输，或在有限回合内重试；不生成无限任务 |

状态包括 revision/tick/epoch、bodyOwner、attribution、endingLock、待执行队列、压力、种子及回合日志。双方同轮观察同一 revision，先分别校验，再在一次核心事务里处理冲突；不能因为第一方先提交而将第二方误判为过期。陌生动作、错误证据、已提交顺序、过期版本一律拒绝。

固定对手根据种子从未解决对象中选择策略。最大六轮；有效回应消解对应主张，反复无效动作消耗预算。保存/调序不自动算作达成目标。记录只含游戏事件，回放不执行模型输出。

## 本地化和存档

- 新入口 `local-version/index.html`，本地程序默认进入此页。普通剧情与现象战争两种模式共享经过核验的文本。
- 物理存档分 `story` 与 `tech` 命名空间。原网页五个既有键与附加实验键保留逻辑名称，通过适配层重定向；原网页入口不改存档。
- 可信主进程只接受白名单存档键和有大小上限的 JSON。先写临时文件并同步，再替换正式文件；读失败时验证备份。
- 导入导出由玩家点击，并使用系统文件选择器；不读取其他个人文件。迁移保留原 area/flags/counters/trials/agency/META；仍由原游戏读档验证恢复。
- 主进程不暴露通用 IPC、fs、shell、spawn 或 URL 请求接口。渲染器外部网络默认拒绝。
- 停止 AI 取消当前请求；关闭窗口取消全部本游戏请求、完成存档并结束宿主。用户已有 Ollama 服务不由游戏启动或终止。

## 阶段与验收

- P0：最新源码与旧美术合并，冻结存档键、触发点和无意识边界。
- 本地化：便携 `EFF.exe`、打包脚本、独立文件存档、离线原文游戏、退出清理。
- P1：五动作 schema、纯仲裁、两方冲突、版本/证据拒绝与重放测试。
- P2：三种操作模式、状态关系可视化、受理轨迹、规划暂停与刷新恢复、完整原文衔接。
- P3 接口：可选既有 Ollama；取消、超时、坏 JSON、无效动作与服务缺席均回退，无任何模型自动下载。
- 后续：真实小模型基准、硬件推荐、Wasm 资源隔离、虚拟规则演化。首版不宣称这些已完成。

验收同时使用原九结局流程回归、纯状态机及主进程权限测试、真实 Electron 窗口启动/离线/存档/关闭检查。Node VM 继续只作原游戏测试工具，不作为不可信代码沙箱。原作对齐验收独立于代码相等；未经证据不能称实验解释为小说事实。
