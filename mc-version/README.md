# EFF · Minecraft 表象融合旁支

版本：**0.1.0 原型**。针对 **Minecraft Java 26.3 / Fabric Loader 0.19.5 / Fabric API 0.163.0+26.3 / Java 25**。

这次将 EFF 的规则与剧情接入 MC 原生世界：玩家和两个本地策略代理争夺身体控制、归责与结局的提交条件。MC 的实体约束、世界时间、场地方块和出口实际参与判定。屏幕撕裂使用 MC 当前渲染目标的真实画面，随后显示已提交的运行状态并重建场景。

当前主要验收入口是**血色庭院争夺练习**；另有从镜像回廊开始的原文之旅。后者加载仓库现有的完整剧情脚本、场景与选择，包括终章的文字操作和介入时序。MC 中的场景美术与全篇逐章通关仍需继续打磨和验收，不能把原脚本回归通过当成完整 MC 通关记录。

## 安装与试玩

普通玩家：

1. 在 Minecraft Java **26.3** 中安装 [Fabric Loader](https://fabricmc.net/use/installer/)。
2. 将 `eff-minecraft-runtime-0.1.0.jar` 与 **0.163.0+26.3** 的 Fabric API 放入该实例的 `mods` 目录。
3. 安装 **Node.js 22 或更新版**，使 `node` 可在 PATH 中运行；剧情宿主与本地模型桥接随模组打包，不需要 `npm install`。
4. 进入单人世界，按 **R** 打开 EFF 菜单。首次可选择“进入争夺练习”，再用正文入口体验剧情。

若启动器的 PATH 中没有 Node，可添加 JVM 参数 `-Deff.node=C:/实际位置/node.exe`。模组首次启动会将随包脚本提取到 MC 实例的 `config/eff/runtime/<内容哈希>/`。已有世界若未加载新维度，需要退出并重新打开世界。

开发环境也可以直接试玩：

```powershell
cd mc-version
# JAVA_HOME 指向 JDK 25；需要 Node.js 22+
.\start-dev.ps1 -Preview
```

该入口在独立 `run/` 目录创建或重开 `eff-playground` 试玩世界，使用固定开发身份保存进度，不会打开启动器里的其他存档。进入庭院后先暂停，按 **P** 开始。首次运行会由 Loom 从官方源下载开发所需的 MC 资源；发行包不包含 MC 本体。

## 操作

| 操作 | 行为 |
| --- | --- |
| WASD / 鼠标 | 在 MC 场景中移动和观察；界面打开时使用鼠标操作 |
| R 或 `/eff` | 打开 EFF 界面 / 模式入口 |
| V | 靠近调查，或继续当前段落 |
| 空格 | 在 EFF 界面中继续；输入框内保留文本输入 |
| 鼠标滚轮 / PgUp / PgDn | 回看当前全文；长段落不会因窗口高度被删掉 |
| “选择与操作”页 | 原脚本的剧情选择、身体碎片、过程回写、接雨水与终章文字按钮 |
| P | 在 EFF 界面暂停 / 继续；模型推理期间回应时限也暂停 |
| Esc / 点击演出 | 略过撕裂演出；不替玩家提交争夺结果 |
| “减少动效” | 停用画面位移，保留文字和判定结果 |
| `/eff play`、`/eff duel` | 进入原文之旅 / 独立争夺练习 |
| `/eff leave` | 随时退出，恢复原位置、游戏模式、能力与原先的冻结状态 |

争夺练习有 **24 秒回应窗口、最多 6 轮**。先选要回应的对象，亲自提交，或让面向拟定建议后决定是否采用。模型的建议本身不改变世界。超时会让外来者接管身体行动；退出入口仍然可用。

## 本地 AI 与双代理

使用现有 Ollama 服务，固定连接 `127.0.0.1:11434`。在“本地模型”页检测并启用已安装的模型；开发试玩入口会优先启用本机已有的 `qwen3.5:4b`。不会自动下载权重。

- 面向代理读取玩家目标与同一版公开战况；外来者读取公开战况，不能读取玩家私有意图或另一代理尚未提交的草案。
- 两者接收 MC 服务端给出的有限运行事实，例如冻结状态、场景代数与出口状态。
- 模型只能选择规则核提供的候选动作。JSON 结构、版本、证据和目标由规则核重新校验后，两侧提案在同一轮结算。
- 界面显示 `local-model` 或 `rule-template` 的来源及后备原因；检测不到服务、模型超时或返回无效数据时，明确使用规则后备。
- `patient` 档允许每侧最多 45 秒；初次加载可能比后续轮次慢。暂停时限不等于 MC 进程卡死，可取消推理。

本机已验证 `qwen3.5:4b` 从 MC 内完成两侧推理，并由 MC 世界接收结果。具体硬件、时延和代理选择依赖当前机器，不作为其他设备的性能保证。

## 真正改变了哪些 MC 状态

| 争夺对象 | MC 中的执行 |
| --- | --- |
| 身体执行权 | 服务端约束玩家位置；回应成立后解除他者牵引；失守后由外来者决定移动轨迹 |
| 世界时间 | 单人服务器的 `ServerTickRateManager.setFrozen`；夺回身体执行权后恢复流动，退出时恢复进入前状态 |
| 强加的归责 | 单独改变现场指认状态，保留身体和已经发生的遭遇；不把“拒绝指认”演成抹掉死者 |
| 结局提交 | MC 红色屏障的真实方块状态与出口谓词；独立练习胜利后可穿过出口离开 |
| 表象重建 | 在同一专用维度生成新的场地投影并迁移玩家；原有 MC JVM 持续运行 |
| 终章过程争夺 | 先记录现场方块检查点，再在原文授权介入与回写之后分段恢复；介入前不提前恢复过去 |

这是服务于叙事的 MC 运行状态适配。**不会让模型任意改写 MC 字节码，也不会真的崩溃或替换用户的 MC 进程。** 代码层外露为只读的已提交状态；“失去响应—重新构成”由真实帧捕获与新场地生成共同演出。

## 原文与美术

正文、终章节点、家庭概率分支、庭院反抗与黄昏接雨沿用现有 EFF 脚本。头像直接复用 `pixel-version/pixel-art.js` 的整数像素绘制，包括周防的血迹和“？？？”的未知身份，不另写一套说话者判断。

八处场景映射为 MC 方块场地；人物与调查点采用原生实体和标记，家庭人物随原脚本站位更新，碎片随原存档收集状态消失。雨塔使用向上运动与倒置身体表象；心象雨水和终章的称谓与介入节点仍由原脚本决定。

3D 角色目前以 MC 原生模型代理呈现，属于原型美术；尚未完成每名人物的独立 3D 模型或整套资源包。

## 构建与验证

```powershell
.\gradlew.bat build
node --test tests/bridge.test.cjs
# 启动独立测试世界，执行真实 MC 验证并自动退出
.\gradlew.bat runClient -PeffSelftest
# 开发试玩；此入口不会自动替玩家出招
.\gradlew.bat runClient -PeffPreview
```

Gradle Wrapper 固定为 **9.8.1** 并校验分发包 SHA-256。`build` 会运行桥接检查，然后生成 `build/libs/eff-minecraft-runtime-0.1.0.jar`。

当前验证覆盖：桥接协议、过期请求拒绝、独立存档、雨滴身份、原文回应顺序与头像；既有剧情和规则检查；原生 MC 中的进入与返回、真实 tick 冻结与释放、双代理推理、结局拒绝后的新场地、超时占据，以及自有桥接进程异常后恢复原世界。测试世界、截图、模型证据与运行日志留在本地 `run/` 或工作区输出，不进入发行源文件。

目前只接受**单人模式**。有其他玩家加入时会退出并恢复冻结状态。渲染采用当前 MC 的 RenderPearl / GUI 提取接口；本机 OpenGL 路径已验证，Vulkan 与其他渲染模组的组合尚未验收。

## 工程结构

- `bridge/headless-story.cjs`：原有脚本的文档和时钟适配；仅执行打包的可信源码。
- `bridge/story-host.cjs`：原文状态、可见交互、头像整数像素与存档投影。
- `bridge/session.cjs`：有限协议、双代理、规则结算与 MC 事实输入。
- `EffServer` / `BridgeProcess`：服务端权威、带版本的状态回传、自有 Node 子进程与退出恢复。
- `EffArena`：专用维度、方块、实体、时间、出口与过程检查点。
- `EffScreen` / `NativeTheatre`：MC 原生界面、真实帧切片与重建演出。
- `EffSelfTest` / `EffPreview`：显式开发开关启用的验收和试玩入口，普通安装不会自动创建测试世界。

接口与实现边界见 [技术说明](./TECHNICAL.md)。原著及现有改编的说明沿用仓库 [主 README](../README.md)。Minecraft 与 Fabric 的安装以各自官方说明为准。
