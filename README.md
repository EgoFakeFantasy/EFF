# 无中归来者

《无中归来者》是一款改编自 SF 小说网《混沌树海》周防篇、以原文叙事为核心的网页游戏。当前主要开发版本为 **第四版 · 现象战争（local-version，v0.6.0）**，以像素箱庭版为基础，增加本地双代理、可操控的运行世界与全窗口现象演出。像素箱庭版通过区域探索、人物对话、记忆收集与直接作用于文字和现象的互动，呈现周防的经历。

**[进入第四版](https://egofakefantasy.github.io/EFF/local-version/)** · **[下载 Windows 本地版](https://github.com/EgoFakeFantasy/EFF/releases/tag/v0.6.0)** · [在线游玩像素箱庭版](https://egofakefantasy.github.io/EFF/pixel-version/) · [箱庭版详细说明（含剧透）](./pixel-version/README.md)

### MC 原生代码保护、恢复与验收

MC 最新发布为 **[EFF Minecraft 0.8.0](https://github.com/EgoFakeFantasy/EFF/releases/tag/mc-v0.8.0)**，面向 MC 1.20.1 / Forge 47.4.20+。本次整合玩家及场景实体生命周期保护、实体登记/渲染/tick 独立诊断、来源认证与最终 Java 转换边界、可选原生隐藏类边界，以及外部录制与原对象证据核对。普通模组、固定平台的实验运行包和源码分别提供，安装与适用范围见 [0.8.0 说明](./mc-forge-1.20.1/RELEASE_0.8.0.md)。

最近手动交战的录像中，双端 29 次采样保留全部 10 个原对象，玩家 tick 持续推进；随后客户端在实体 tick 容器迭代时发生越界异常并停止服务器。因此本版保留实体保护的有限证据，同时公开客户端稳定性缺口，不声称完整持续存活或任意原生攻击免疫。恢复、原实体存活和窗口可用性分别记录，重启或重生不能替代原对象持续存活。

[手动实战模式](./mc-1.20.1/MANUAL_COMBAT.md)与[外部窗口录制器](./mc-1.20.1/WINDOW_RECORDING.md)支持用户操作、按原 PID/HWND 和对象身份复核；[参数隔离](./mc-1.20.1/ARGUMENT_ISOLATION.md)与来源认证用于启动期及后续 Java 转换边界。普通模组不自动安装原生组件，实验边界也不等于操作系统隔离。

这里的“运行内核”指 EFF 的规则、外部权威状态与监督进程。现有生产守护由 C# `WindowsGuard.cs` 实现，Java 的执行／判定引擎在独立 JVM 中运行；它不是 Windows 内核驱动。新增 Rust 监督层属于可选实验，见[工程蓝图及验证状态](./mc-1.20.1/RUST_SUPERVISOR_BLUEPRINT.md)和[实现](./mc-1.20.1/runtime/rust-supervisor/)，不能由使用 Rust 推断获得了更高系统权限。

**原生攻击面。** JNI、JVMTI、Instrumentation、Unsafe 和 DLL 加载能跨越普通 Java 对象接口；其中 JNI/DLL 会在 MC 地址空间执行机器码。C、C++、Rust 是实现语言，权限由进程令牌、对象访问控制和操作系统决定。在同一 JVM 中，攻击代码可以改写对象、类与注册表结构，也能让自己的 JVM 退出；保护外部进程不会自动保护这个 JVM 内部的每个实体。仅修改 UUID、反复设回血量或者换一个 Java 类名，不构成可靠的原生权限边界。

**受保护启动。** 显式准备阶段封存 JDK、classpath、映射、原生库、模组及启动配置，保存文件哈希并持有防替换句柄。实际启动只验证既定基线，不接受攻击进程提供的新路径、参数、插件目录或环境变量，也不会在失败后把被修改的文件重新签成可信版本。额外模组要做能力审查；默认拒绝和隔离策略不会因为实验通过而自动解除。无法兼容的启动期自检应报告为失败，而不能悄悄删掉对手逻辑后声称打赢原版。

**外部权威与 Windows 边界。** 模型输出只是受限提案。外部控制台、宿主观察和模型身份分别验证；MC 的生命值观察不能直接重写权威战果。外层独立保存带 DPAPI 密钥保护的 HMAC 链日志、日志头与递代关系，拒绝权限复活、版本回退和终局反转。实验性 Low 模式移除继承特权，对权威目录、控制器和工作 JVM 设置禁止低完整性读取／写入／执行的标签，并检查进程属于当前 Job。Windows 执行这些访问检查；默认 Low 标签仅禁止向上写入，不能省略额外读保护。完整进程树由 Job Object 管理，退出时清理后代，有限预算耗尽后停止。

**两种不同目标。** 当前 JVM 递代可生成并验证新的受限执行类，在新 JVM 中接续已提交状态；控制器或宿主恢复可能需要退出旧 MC。这是恢复能力。实体连续存活的交战验收另外要求：原实体对象与 UUID 未被替换，健康／死亡／移除／世界注册状态持续正常，对手确实发生攻击，且同一 MC 进程的游戏窗口保持响应。MC 崩溃、被清除后重建、只保住权威日志或隔离结束都不能算交战通过。

**Rust 监督层的有限重建。** 一个固定 Rust root 核验映像、配置、Guardian 与 manifest，先持久消耗预算，再启动可替换的 Rust 子监督器。子层失败后先排空旧 Job，再允许后继；不会继承对手提供的程序、环境或新权限。已用真实 C# Guardian、双 JVM 和测试子孙进程验证子层替换、整树清理、撤权保留与 root 死亡时清理；这项测试没有加载 MC 或对手模组。默认启动器暂未启用该实验层。Rust 心跳只说明监督循环仍活着，尚不能覆盖 Guardian 内部无进展但未退出的所有情况。

当前 Rust 重置使用同一已封存二进制，重建进程上下文；它不同于 JVM 的受限新类生成，不宣称每代重新编译 Rust 机器码。最外层 root 本身仍需更外部的固定验证者才能被安全接管，递归不会消除这个信任基础。

**严格实验入口。** `runtime/guard/foreign-sword-native-test.cjs` 和 `pig2-native-test.cjs` 共用显式隔离实验流程，固定样本 SHA256，记录原对象的失败锁存、持续观察和独立窗口探针。`WindowProbe.cs` 从 MC 外侧检查受信任控制台报告的 PID、游戏窗口和响应，排除普通错误弹窗／控制台。判定器缺少真实攻击、干净基线或窗口证据时返回 `INCOMPLETE`，检测到死亡／清除／崩溃时返回 `FAILED`。Pig2 的私有字段快照只能证明目标和阶段，不能冒充高级攻击入口已执行。所有观察都有采样盲区；敌对同进程代码也可能伪造 Java 观察，因此有限试验不是任意原生攻击下的不死证明。原包版本及已证实／未证实的触发条件见[对手审查记录](./mc-1.20.1/LATEST_OPPONENT_AUDIT.md)。

**更低层的工程边界。** 用户态监督器依赖 Windows 内核，无法靠递归复制超过它。若威胁模型包括被攻陷的 Windows 内核，需要把最终权威与恢复决策移到独立宿主、经过维护的虚拟机监控层或另一台机器；这仍依赖相应的宿主／硬件信任根。VM 回滚也不满足“MC 从未崩溃”。若要隔离任意原生对手同时保证可信 MC 连续运行，需将对手移到另一个进程或 VM，通过受限协议作用于可信世界；这样会改变原模组在同一 JVM 内的执行语义，必须另行验证，不能冒称原版同进程对抗已经成功。

参考：[Microsoft MIC](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control)、[原生进程对象权限](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights)。本项目不关闭系统安全防护，不安装未签名保护驱动，也不把进程设为不可结束的系统关键进程。

**网站根地址仍然进入原版文字游戏。** 第四版的地址包含 `/local-version/`；合并到 `main` 不会自动改变首页入口。

## 像素箱庭版体验

- 八个章节场景、八枚可跨周目保留的记忆碎片，以及九种结局。调查顺序与剧情选择会影响进程。
- Canvas 像素场景与人物头像，包括分层材质、家具细节、场景光影，以及与正文同步的人物姿态和镜头切换；以设备像素整数倍缩放并对齐相机像素，增强颗粒清晰度。
- 根据小说正文校正说话者与问答顺序，补回镜像阶段的推理及庭院的松手动作；新增木面、空床铺、水潭、裂隙调查，点击对象可标记或在近处调查。
- 暴雨圆塔中向天空的红月逆落；日常场景随人物行动转换地点；血色庭院以身体血迹和侵入全屏的话语呈现夺权压力。
- 战斗围绕身体所有权、表象和过程的改写展开。玩家选择回应对象、比较被覆盖的文字，并在剧情允许时回到过去介入事件。
- 新增作者指定的改编机制：日常停留的概率锁定、庭院限时反抗，以及黄昏之海接雨水。三条失败分支各有独立结局，暂停与检查点同时覆盖这些操作。
- 终章保留完整原文节点，以回溯插入、故事覆盖、前传回声和整章回写承载操作，而不是将正文压缩为探索提示。
- 像素光影：各区域有自己的光源（镜面、棺木铭文、窗光、电视、厨房、余火、红月、水潭），阴影以有序抖动量化在整数像素上；尚未调查的事物会微微发光，读过后归于安静。人物有四帧步行、侧面轮廓、摆臂与眨眼，地面有裂纹、磨损、污渍与镶嵌等变化，脚步在雨地溅起水花。
- 剧情转折处的像素演出：离开镜像回廊时画面碎裂坠落、躺入棺材时棺盖合上并收成一道缝、在床上醒来时睁眼眨动并弹起、血色庭院先在原地裂开并闪过雪花纹，再随「场地不断下落」碎成泡沫与无色的雨水；母亲端菜时也会迈步行走。
- 程序化音乐：每个区域一段 Web Audio 即时合成的主题（镜廊的清冷琴音、花园的八音盒、空屋稀疏的不协和音、家中的暖和弦、庭院的心跳、雨塔的小调琶音、终章的五度上行，真结局与坏结局各有收尾），以及镜碎、棺盖、醒来、庭院崩裂与坍落、拾取碎片的音效。随「音景」开关，设置中可单独关闭背景音乐。
- 九种结局各有一张依据结局正文绘制的像素插图，例如 BAD END 04 是黄昏中的早餐桌与窗外的海，真结局「无垠之萍」是浮萍水面上留住一滴雨水的手。
- 调查标记区分「未调查 / 尚未开启 / 已调查」，探索栏与地图显示本区调查进度；靠近未拾取的记忆碎片时，碎片发光、闪烁并以渐高的音色共鸣。
- 对白可开启「自动」，或用「快进已读」/ 按住 Ctrl 跳过任何周目读过的句子；遇到未读句子、选择、现象写入、挑战与终章的可点击回答时停下。
- 提供回读、记忆图鉴、区域地图、探索提示、文字速度、音量、减少动态与闪光、光影与暗角设置。程序化音景默认关闭，可手动开启（含按地面材质变化的脚步声）。

演出与玩法以原文含义、说话者身份和事件顺序为依据。具体剧情机制与结局条件见[箱庭版说明](./pixel-version/README.md)。

## 本地运行

项目为纯静态 HTML / CSS / JavaScript，无需安装前端依赖或执行构建。可以直接打开对应版本的 `index.html`；开发时建议从仓库根目录启动静态服务器，例如安装 Python 后执行：

```sh
python -m http.server 4179
```

随后访问 `http://localhost:4179/pixel-version/`。持续使用同一地址和端口，便于保留本地存档。

```sh
node tests/pixel-regression.cjs
```

回归测试使用 Node VM 与模拟 DOM / Canvas，检查剧情互动、结局、存档和操作边界；它不能替代真实浏览器中的视觉、音频与触屏体验检查。GitHub Actions 的 `Check pixel game` 工作流负责自动检查。

本轮人物动作、庭院夺权、接雨与身体合一的画面规则及可选浏览器验收，见[像素演出样段说明](./docs/pixel-art-slice.md)。

`main` 已包含当前箱庭版。推送到 `main` 后，GitHub Actions 的 `Deploy static game to GitHub Pages` 工作流发布仓库根目录；也可手动触发。四个版本分别保留各自路径。

部署到其他静态托管服务时，上传完整仓库站点文件并保留目录结构即可。


## 第四版 v0.6.0：双代理现象战争

新增独立入口 [local-version](./local-version/README.md) 与 Electron Windows 宿主，复用当前箱庭剧情、美术、过场和音乐。普通模式保持原九种结局；技术模式增加数据式规则编辑、本地模型双代理提案、确定性仲裁与事件重放。守护侧与外来者共享一套本地权重、分别规划，玩家审阅后才执行；模型关闭或单侧失败时分别回退规则模板。默认离线、无模型也可游玩。

实现框架、叙事边界和后续阶段见[本地版技术文档](./docs/eff-local-implementation.md)。双代理接口与实际模型验收见[本地 AI 说明](./docs/eff-local-ai.md)。此新增入口不改变网站根目录的原版入口。

0.4 增加[全窗口现象演出](./docs/eff-screen-spectacle.md)：窗口撕裂、执行轨迹显露、视觉崩溃与虚拟运行实例重建，并在终章呈现原句覆盖与获授权的过去回写。主菜单可直接预览。

0.5 增加[动态世界与原生实例](./docs/eff-live-world.md)：血色庭院的身体输入、结局碰撞边界、归责链与终章过去锚点由同一状态驱动；WebGL2 统一合成像素场景和运行骨架，重建实际切换世界子进程。

第四版精修三种回应的画面：身体牵引回缩并断开，强加的指认剥离，结局封印裂解。运行层只显露实际碰撞轮廓与控制连接；全窗口碎片随争夺对象变化。终章保留完整原句和替代句，授权后的回溯沿同一条历史呈现。重建画面等待原生世界的成功回执，身体位置与已确认的回应接续。

浏览器可预览剧情、规则争夺和视觉演出，使用同一世界规则的浏览器实例；Windows 程序另有文件存档、本地模型连接及实际世界子进程的退出／生成。模型权重需由玩家自行准备，默认关闭，无模型时可用规则模板完整游玩。演出可暂停、略过，并支持减少动态。

第四版的演出与实际操控关系见[第四版说明](./docs/eff-fourth-edition.md)。
